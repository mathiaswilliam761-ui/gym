# GymApp - Preview Build Process & Deployment Guide

## Overview
This document describes the complete process for building, testing, and deploying GymApp preview builds to TestFlight (iOS) and Google Play Internal Testing (Android).

---

## Prerequisites

### Required Tools
- **EAS CLI**: `npm install -g eas-cli`
- **Expo CLI**: `npm install -g expo-cli`
- **Apple Developer Account** (for iOS/TestFlight)
- **Google Play Console Access** (for Android)

### Required Configuration Files (Already in repo)
- `eas.json` - Build profiles
- `app.json` - Expo config with bundle identifier
- `credentials.json` - (Generated by EAS)

---

## 1. Initial Setup (One-time)

### Login to EAS
```bash
eas login
```

### Configure Project
```bash
cd /opt/data/gym-app
eas build:configure
```

### Register iOS Device (for development builds)
```bash
eas device:create
# Scan QR with iPhone camera to register UDID
```

## 2. Build Profiles (eas.json)

```json
{
  "cli": {
    "version": ">= 9.0.0",
    "appVersionSource": "remote"
  },
  "build": {
    "development": {
      "developmentClient": true,
      "distribution": "internal",
      "channel": "development",
      "ios": { "simulator": false }
    },
    "preview": {
      "distribution": "internal",
      "channel": "preview",
      "ios": { "simulator": false }
    },
    "production": {
      "distribution": "store",
      "channel": "production",
      "autoIncrement": true
    }
  },
  "submit": {
    "production": {}
  }
}
```

| Profile | Purpose | Distribution |
|---------|---------|--------------|
| `development` | Custom dev client with native modules | Internal (Ad Hoc) |
| `preview` | TestFlight / Play Internal builds | Internal |
| `production` | App Store / Play Store | Store |

## 3. Development Build (For Background GPS Testing)

### iOS
```bash
eas build --profile development --platform ios
```

### Android
```bash
eas build --profile development --platform android
```

### Install on Device
1. Build completes → Get download link from EAS dashboard
2. iOS: Open link on iPhone → Install profile → Trust developer in Settings
3. Android: Open link → Download APK → Install

### Test Background GPS
1. Open app → Cardio tab → Start "Running"
2. Lock phone, put in pocket
3. Walk 200m+ outdoors
4. Unlock → Verify route/distance recorded

## 4. Preview Builds (TestFlight / Play Internal)

### iOS - TestFlight
```bash
# Build
eas build --profile preview --platform ios

# Submit to TestFlight
eas submit --platform ios --profile preview
```

**TestFlight Setup:**
1. App Store Connect → TestFlight → Add new build
2. Add internal testers (emails)
3. Testers get email with TestFlight invite

### Android - Play Internal Testing
```bash
# Build
eas build --profile preview --platform android

# Submit to Play Console
eas submit --platform android --profile preview
```

**Play Console Setup:**
1. Play Console → Testing → Internal testing
2. Create release → Upload AAB from EAS
3. Add testers by email

## 6. GitHub Actions CI/CD (Optional)

Create `.github/workflows/eas.yml`:

```yaml
name: EAS Build & Deploy

on:
  push:
    branches: [main]
    tags: ['v*']
  pull_request:
    branches: [main]

jobs:
  build-preview:
    name: Build Preview
    runs-on: ubuntu-latest
    if: github.event_name == 'push' && !startsWith(github.ref, 'refs/tags/')
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: '20', cache: 'npm' }
      - run: npm ci
      - run: npx eas-cli build --profile preview --platform all --non-interactive --no-wait
        env:
          EXPO_TOKEN: ${{ secrets.EXPO_TOKEN }}

  build-production:
    name: Build Production
    runs-on: ubuntu-latest
    if: startsWith(github.ref, 'refs/tags/v')
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: '20', cache: 'npm' }
      - run: npm ci
      - run: npx eas-cli build --profile production --platform all --non-interactive
        env:
          EXPO_TOKEN: ${{ secrets.EXPO_TOKEN }}
      - run: npx eas-cli submit --platform all --profile production --non-interactive
        env:
          EXPO_TOKEN: ${{ secrets.EXPO_TOKEN }}
          ASC_API_KEY_ID: ${{ secrets.ASC_API_KEY_ID }}
          ASC_API_KEY_ISSUER: ${{ secrets.ASC_API_KEY_ISSUER }}
          ASC_API_KEY: ${{ secrets.ASC_API_KEY }}
          GOOGLE_SERVICE_ACCOUNT_JSON: ${{ secrets.GOOGLE_SERVICE_ACCOUNT_JSON }}
```

### Required Secrets (GitHub Settings → Secrets)
| Secret | Purpose |
|--------|---------|
| `EXPO_TOKEN` | `eas token:create` |
| `ASC_API_KEY_ID` | App Store Connect API Key ID |
| `ASC_API_KEY_ISSUER` | App Store Connect API Key Issuer |
| `ASC_API_KEY` | Base64 encoded .p8 file |
| `GOOGLE_SERVICE_ACCOUNT_JSON` | Base64 encoded service account JSON |

## 6. Over-the-Air Updates (Expo Updates)

### Publish Update
```bash
eas update --branch preview --message "Bug fix: rest timer haptics"
```

### Configure Auto-Update (app.json)
```json
{
  "expo": {
    "updates": {
      "enabled": true,
      "checkAutomatically": "ON_LOAD",
      "fallbackToCacheTimeout": 30000
    },
    "runtimeVersion": {
      "policy": "appVersion"
    }
  }
}
```

## 7. Versioning Strategy

### Automatic (Recommended)
```json
// eas.json production profile
"autoIncrement": true
```

### Manual
```bash
# Patch (1.0.0 → 1.0.1)
eas build --profile production --auto-increment=patch

# Minor (1.0.0 → 1.1.0)
eas build --profile production --auto-increment=minor

# Major (1.0.0 → 2.0.0)
eas build --profile production --auto-increment=major
```

## 8. Troubleshooting

### Build Fails - "No profiles for bundle identifier"
```bash
eas credentials --platform ios
# Select "Configure new" → "Create new provisioning profile"
```

### Build Fails - "Java heap space"
```bash
# Add to eas.json build profile
"android": {
  "gradleCommand": ":app:bundleRelease",
  "env": { "GRADLE_OPTS": "-Xmx4g" }
}
```

### TestFlight - "Missing compliance info"
- App Store Connect → App → App Information → Encryption → "No"

### Play Console - "Target API level"
- Update `compileSdkVersion` and `targetSdkVersion` in app.json

## 11. Post-Deploy Checklist

- [ ] TestFlight build processes (10-30 min)
- [ ] Internal testers can install
- [ ] Background GPS works on physical device
- [ ] Offline mode works (airplane mode test)
- [ ] Sync indicator shows correct status
- [ ] Error boundaries catch crashes gracefully
- [ ] Maestro E2E tests pass on device
- [ ] Analytics events firing (if configured)

## 12. Rollback Procedure

```bash
# If production build has critical bug
eas build --profile production --platform all --auto-increment=patch
eas submit --platform all --profile production

# Or promote previous build
# App Store Connect: "Submit for Review" previous version
# Play Console: "Rollback" in Internal Testing
```
